■ 0. 全体像（これだけ読めば足りる）

  この checkstyle.xml は「コーディングスタイル統一」のための単独のゲート。
  中身は Sun/Google 公式設定にもある標準モジュールだけで構成し、値も
  一般的なもの（4スペース・K&R・折返し120・標準命名・定番の品質チェック）。
  フォーマッタを使うかどうかにも、SonarQube の有無にも依存しない。
  （Sonar と一部指摘が重複するが、重複は害ではなく多層防御として扱う）

  redhat.java（VS Code の Java 拡張）との関係は1つだけ：
    「redhat.java の既定フォーマッタで整形したコードが、この checkstyle に
      落ちることはない」（実測56ファイルで検証済み）。
    整形は義務ではないが、使えば機械的に通る状態になる、という位置づけ。
    ※拡張の機能24個のうちコードの形に関わるのは Code formatting と
      Organize imports の2つだけ。121個の設定項目は IDE の動作設定であり、
      checkstyle に「適用」する類のものではない。

■ 1. checkstyle.xml 全43モジュールの内訳

  【レイアウト：17個】（4スペース・K&R・120。redhat.java 既定出力と両立）
  NewlineAtEndOfFile      ファイル末尾に改行（POSIX 慣習・diff 汚れ防止）
  FileTabCharacter        タブ禁止
  LineLength (max=120)    折返し 120。package/import/URL 行は折返し不能のため除外
  RegexpSingleline (\s+$) 行末空白の禁止
  Indentation             基本4・case 4・配列初期化子の継続8
  LeftCurly               開きブレースは行末（K&R）
  RightCurly              else/catch は } と同じ行
  WhitespaceAround        演算子・キーワード前後の空白（空ボディは許容）
  WhitespaceAfter         カンマ・セミコロンの後に空白
  NoWhitespaceBefore      カンマ・セミコロンの前に空白なし
  NoWhitespaceAfter       単項演算子・ドット等の後に空白なし
  GenericWhitespace       ジェネリクス <> まわり
  ParenPad                ( ) の内側に空白なし
  MethodParamPad          メソッド名と ( の間に空白なし
  TypecastParenPad        キャストの ( ) の内側に空白なし
  SingleSpaceSeparator    連続空白（手動アライン）禁止

  【import：3個】
  AvoidStarImport         スター import 禁止
  RedundantImport         重複・同一パッケージ import の禁止
  UnusedImports           未使用 import の禁止

  【命名：8個】（全て checkstyle 既定パターンのまま）
  PackageName             パッケージ名（小文字）
  TypeName                クラス/インターフェース名（UpperCamel）
  ConstantName            定数名（UPPER_SNAKE）
  MemberName              フィールド名（lowerCamel）
  MethodName              メソッド名（lowerCamel）
  ParameterName           引数名（lowerCamel）
  LocalVariableName       ローカル変数名（lowerCamel）
  LocalFinalVariableName  final ローカル変数名（lowerCamel）

  【品質系（バグの温床になりやすいコード）：11個】
  EqualsHashCode          equals/hashCode の片方だけのオーバーライド禁止
  StringLiteralEquality   文字列の == 比較禁止
  EmptyStatement          空文（; だけ）の禁止
  EmptyBlock              空ブロック禁止（コメントがあれば許容）
  FallThrough             switch の暗黙フォールスルー禁止
  MissingSwitchDefault    switch に default 必須
  SimplifyBooleanExpression  冗長な boolean 式の禁止（== true 等）
  SimplifyBooleanReturn   冗長な boolean return の禁止
  NeedBraces              if/for/while は必ずブレース
  OneStatementPerLine     1行1文
  MultipleVariableDeclarations  1文1変数宣言

  【ファイル構成・その他：5個】
  OuterTypeFilename       公開型名とファイル名の一致
  OneTopLevelClass        1ファイル1トップレベルクラス
  ModifierOrder           修飾子の順序（public static final 等）
  ArrayTypeStyle          String[] args 形式（String args[] 禁止）
  UpperEll                long リテラルは大文字 L

■ 2. 入れていないもの（理由付き）

  import の並び順 (CustomImportOrder)
      正解の並び順をチームで決めていないため。決めたら追加する
      （redhat.java の organize imports を併用するなら
        java.completion.importOrder と一致させること）
  メンバー間の空行 (EmptyLineSeparator)
      空行の入れ方は書き手の裁量に残す判断。強制したければ追加可能
  折返し位置 (OperatorWrap / SeparatorWrap)
      演算子の前で折るか後で折るかを決め打ちすると、redhat.java の
      整形結果と矛盾する恐れがある（細部設定依存・未検証）。
      「120で折り返す・継続行のインデント」は LineLength + Indentation で担保済み
  アノテーション配置 (AnnotationLocation)
      同上（checkstyle 既定と整形結果の一致が未検証）
  Throwable キャッチ禁止 (IllegalCatch)
      MyBatis Interceptor 等、API が catch(Throwable) を強制する場面が
      あり、正当なコードが書けなくなるため

  ※判断基準：標準的で手直しも容易なものは入れる。
    「整形ツールの結果と矛盾し得るもの」「チームの取り決めが先のもの」
    「正当なコードを禁止してしまうもの」は入れない。

■ 3. VS Code 側の推奨設定（任意。checkstyle に自動で通る環境を作る）

  checkstyle はフォーマッタなしでも成立するが、以下を設定しておくと
  保存するだけで大半のルールを満たせる：

    editor.formatOnSave = true
    "[java]": { "editor.defaultFormatter": "redhat.java" }
    editor.insertSpaces = true / editor.tabSize = 4（VS Code 既定のまま）
    files.insertFinalNewline = true        （NewlineAtEndOfFile 対応）
    files.trimTrailingWhitespace = true    （行末空白対応）
    editor.codeActionsOnSave: { "source.organizeImports": true }
                                           （不要 import の自動除去）

  redhat.java 側の関連設定（既定のままでよい）：
    java.format.enabled / java.format.settings.url（チーム配布時のみ）/
    java.completion.importOrder / java.sources.organizeImports.starThreshold

  エディタで checkstyle 違反を見たい場合は別拡張
  「Checkstyle for Java (shengchen.vscode-checkstyle)」に
  同じ checkstyle.xml を指定する。

■ B. Quick Start / JDK 要件

  1. 拡張機能をインストール
  2. win32-x64 / win32-arm64 / darwin-x64 / darwin-arm64 / linux-x64 /
     linux-arm64 ではセットアップ不要（JRE 同梱）。それ以外・universal 版は
     言語サーバー用に Java 21 以上が必要
  3. プロジェクト用 JDK を用意（Java 1.8 以上対応）
  4. Java ファイルを開くと有効化、Maven/Gradle ビルドファイルを自動認識
  ・プロジェクト JDK の切替は java.configuration.runtimes
    （JavaSE-1.8 / 11 / 25 / 26 等の名前とパスを列挙、default 指定可）
